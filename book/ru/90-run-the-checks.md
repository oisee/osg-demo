# Приложение A. Запуск проверок

В checkout open-steamgate один раз выполните `npm install && npm run bootstrap`. Затем `OSD_HOME=/path/to/open-steamgate node test/slice.mjs` собирает этот checkout движка с данной папкой в качестве пака (pack), запускает его на свободном порту и проверяет флот дирижаблей от начала до конца: шесть кораблей в `ShipSet`, classrun отчёта по флоту, `$filter` по статусу, MERGE с последующим чтением, плитку launchpad, открывающую list report (для этой проверки нужен браузер с доступом к ui5.sap.com; `SLICE_SKIP_UI=1` пропускает её и сообщает об этом, `SLICE_CHROMIUM=<path>` выбирает браузер), и тест ABAP Unit отчёта. Используйте основную ветку движка на `0ba17ed` или новее: плитка открывает приложение через intent launchpad, который более старые движки не разрешают для пака. Скрипт останавливает запущенный им движок и завершается с ненулевым кодом, если какая-либо проверка не прошла. `OSD_HOME=/path/to/open-steamgate node test/jobs.mjs` так же проверяет фоновые задания на временном файле SQLite: одно задание с его журналом BAL и обе цепочки (успешная завершается, неуспешная оставляет задание готовности в ожидании).

`OSD_HOME=/path/to/open-steamgate node test/lift.mjs` проверяет, что сгенерированная
область `ZCL_OSD_FLEET_LIFT=>AFTER` совпадает с тем, что рецепт lift отображает из
`BEFORE` (глава 11); `--write` генерирует её заново. Её также выполняет проверка 16 в slice.

| Скрипт | Проверки | Бэкенды | В CI |
|---|---|---|---|
| `test/slice.mjs` | 21: таблицы и seed, предпросмотр F8, classrun, аудит BAL, дерево сервисов, OData, плитка (UI, можно пропустить), тесты ABAP Unit, дамп, zip, AMDP, обе таблицы ALV, отчёт по шаблону, lift | SQLite, DuckDB | да, оба, с пропущенной проверкой UI |
| `test/jobs.mjs` | 7: одно задание, обе цепочки, «доктор» | файл SQLite | да |
| `test/lift.mjs` | поднятая область соответствует своему рецепту | любой | через проверку 16 в slice |
