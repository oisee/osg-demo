# 20. Инструменты возвращаются домой: abaplint на ABAP

open-steamgate активирует ваш ABAP через abaplint — парсер и линтер ABAP,
который [Ларс Хвам](https://github.com/abaplint/abaplint/blob/30c6443c6a16b7998621a630355a2b81daeea977/LICENSE) написал на TypeScript, — и его транспайлер. Глава 18
привезла в ABAP другие языки просто потому, что можно. Эта глава привозит
сам abaplint, переведённый на ABAP и работающий внутри сервера приложений
ABAP.

Переводчик — [abapiti](https://github.com/oisee/abapiti/tree/v0.5.2), тот же проект, что
и в главе 18. Дальше — по
[README abapiti на теге v0.5.2](https://github.com/oisee/abapiti/blob/v0.5.2/README.md)
и по его записи
[весь набор тестов abaplint на трёх рантаймах](https://github.com/oisee/abapiti/blob/b5b19ec/docs/history/2026-10-15-abaplint-tests-on-three-runtimes.md);
прогоны на SAP эта глава не повторяла.

## Дорога

abapiti читает TypeScript abaplint через проверку типов tsgo и потому
начинает с типов, которые она вывела, а не с текста. Он переводит программу в собственное типизированное объектное
представление, HIR, и выводит его одним из двух способов:

- как классы и интерфейсы ABAP, читаемые и импортируемые через abapGit;
- как Go — быструю нативную сборку той же программы.

Оба результата получаются из одного и того же HIR. Ни один из них не перевод
другого.

## Проверка

Переведённый линтер чего-то стоит, только если даёт те же ответы. abapiti не
судит об этом сам. Он берёт собственный набор тестов abaplint — тесты на mocha
и chai, которые написали авторы abaplint, — и компилирует их вместе с ядром
через небольшую прослойку, не переписывая руками ни одного теста.

Эталон — прогон тех же тестов на Node на том же коммите abaplint
(`577f875e`, `@abaplint/core` 2.120.56): 11 092 зарегистрированных, из них 32
пропущены в самом abaplint. Остаётся 11 060. Каждый результат на каждом хосте
сверяется с прогоном на Node по названию теста.

| Хост | Что работает | Проходит | Неверных ответов |
|---|---|---:|---:|
| Go | abaplint, переведённый на Go | **11 060** из 11 060 | 0 |
| Go-рантайм open-steamgate (osgo) | abaplint, переведённый на ABAP | **11 060** из 11 060 | 0 |
| SAP NetWeaver 7.58 (A4H) | тот же ABAP на настоящем ядре | **11 060** из 11 060 | 0 |

В наборе семнадцать частей; самые большие — парсер операторов (4 962 теста),
правила (3 149) и проверка синтаксиса (1 363). На A4H переведённый abaplint —
это 2 338 классов и ещё 5 015 классов тестов; все активируются без
синтаксических ошибок, а самые долгие части идут фоновыми заданиями
24 минуты (правила) и 22 минуты (операторы).

Путь туда, в проходящих тестах на сборке Go, как его записывает README
abapiti: 0, 27, 661, 6 515, 9 022, 10 167, … 11 051, **11 060**.

## От чего отказалось ядро

В первом полном прогоне на A4H прошли 11 055 тестов. Остальные пять споткнулись
о пустое регулярное выражение: `new RegExp("")` в JavaScript его принимает, а
ядро SAP пустой POSIX-regex отвергает. Теперь abapiti пишет пустой шаблон как
`(?:)` — он значит то же самое, и ядро его принимает. Это находка того же рода,
что и список отказов ядра в главе 18: код, который берут все остальные рантаймы,
а настоящая система — нет.

## Линтер проверяет abapGit

Линтер на ABAP — это не только результат тестов. README abapiti измеряет
переведённый abaplint в деле: проверку `zabapgit_standalone.prog.abap`, всех
159 тысяч строк abapGit в одном отчёте, вместе с зависимостями и с
собственной конфигурацией abaplint из abapGit. На каждом хосте найденные
замечания совпадают с замечаниями исходного abaplint на Node байт в байт.

| Где работает abaplint | Время |
|---|---:|
| переведённый на ABAP, ядро SAP 7.58, фоновое задание | 171,5–179,3 с |
| переведённый на ABAP, Go-рантайм open-steamgate (osgo) | 14,3–17,2 с |
| переведённый на ABAP, одна нативная программа, собранная open-steamgate | 17–20 с |
| переведённый на ABAP, JavaScript-рантайм open-steamgate | 85 мин |
| переведённый на Go | 7,9 с |
| исходный, на Node | 14,0 с |

Это abapiti v0.3 (`f9d5f8c`) с open-steamgate `7720f6e2` (JavaScript-рантайм —
`6e10128e`). Go-рантайм, нативная сборка, Go и Node шли на одной машине Linux,
16-ядерной, по словам abapiti, на которой шли и другие задачи; A4H — отдельная
машина. На этой программе JavaScript-рантайм работал 85 минут, Go-рантайм —
четверть минуты.

## Что дальше

abapiti не только переводит. **GRACE**, движок внутри него, выводит факты о
программе поверх HIR (кто кого вызывает, что читается, что меняется) и
выполняет на этих фактах переписывания, например встраивание; завершение,
идемпотентность и равенство инкрементального и полного результата
проверены. Записи abapiti
([движок](https://github.com/oisee/abapiti/blob/v0.5.2/docs/history/2026-10-10-grace-engine.md),
[флаг встраивания](https://github.com/oisee/abapiti/blob/v0.5.2/docs/history/2026-10-10-grace-inline-flag.md))
показывают его первую работу: то же встраивание, что и раньше; результат
совпадает байт в байт.

Есть и отдельный проект в организации abaplint,
[abaplint-abap-classic](https://github.com/abaplint/abaplint-abap-classic):
abaplint для классического Code Inspector и ATC, который ставится через
abapGit и включается в транзакции SCI. Его README называет его бетой для
экспериментов.

## Запустите сами

Сборке Go не нужны ни система SAP, ни open-steamgate: только Node (эта книга
использовала 24.21.0) и Go 1.26.0 в `PATH`, abapiti на теге `v0.5.2` и
abaplint на `577f875e`:

```
git clone https://github.com/abaplint/abaplint /path/to/abaplint
cd /path/to/abaplint && git checkout 577f875e
npm ci
cd packages/core && npm ci

git clone --branch v0.5.2 https://github.com/oisee/abapiti /path/to/abapiti
cd /path/to/abapiti
node tools/abaplint-tests-all.mjs /path/to/abaplint out.json
```

Команда компилирует все семнадцать частей в Go, запускает их, сверяет с
прогоном тех же тестов на Node и печатает таблицу по частям. Эта книга
запустила её с тега на Intel Core i7-10700K (8 ядер, 16 потоков, около 126 ГиБ памяти), Node
24.21.0 и Go 1.26.0, когда на машине шли и другие задачи; прогон занял
49 минут 27 секунд и закончился так:

```
| rules | 3149 | 0 | 0 | 0 | 10 | 3159 | 3149+10 pending |
| utils | 15 | 0 | 0 | 0 | 0 | 15 | 15+0 pending |
| TOTAL | 11060 | 0 | 0 | 0 | 32 | 11092 | 11060+32 pending |
11060/11060 (Node-active only); Node total including pending: 11092
```

Столбцы: успешные, неуспешные, аварийные остановки, асинхронные в ожидании,
не запущенные и зарегистрированные тесты. Последний столбец показывает, что с
тестами части сделал сам Node.

Сборку ABAP можно запустить и на двух других хостах:

- **osgo.** Нужен open-steamgate на `f83dc5c3` — это линия разработки, новее
  тега этой книги:

  ```
  git clone https://github.com/oisee/open-steamgate /path/to/open-steamgate
  cd /path/to/open-steamgate && git checkout f83dc5c3
  npm ci && node tools/osd-libs.mjs
  cd /path/to/abapiti
  ABAPITI_TESTS_TARGET=osg ABAPITI_OSG_HOME=/path/to/open-steamgate \
    node tools/abaplint-tests-all.mjs /path/to/abaplint out-osg.json
  ```

  Та же система опубликована одним
  индексом OCI (`ghcr.io/oisee/abapiti/zlnt-system:v0.5.2`), который
  open-steamgate ставит через `osd-fetch --system`, без клона abapiti. На
  open-steamgate `f83dc5c3` в этом образе ещё 28 тестов падали в трап: двух
  возможностей рантайма в open-steamgate тогда не было; на линии разработки
  на `5bced9f8` тот же образ прошёл все 11 060, без падений и трапов
  ([более поздний раздел записи](https://github.com/oisee/abapiti/blob/0408d2f/docs/history/2026-10-15-abaplint-tests-on-three-runtimes.md)).
- **Настоящая система SAP.** Импортируйте архивы abapGit из релиза в порядке,
  который даёт
  [руководство abapiti](https://github.com/oisee/abapiti/blob/v0.5.2/docs/a4h-test-suite.md),
  запустите отчёт `ZLNT_TESTS_RUN` для каждой части фоновым заданием и сверьте
  таблицу `ZLNT_TESTRUN` с прогоном на Node инструментами abapiti.
